Status HTTP: respostas de sucesso e erro em APIs
➢200 –OK -> Requisição realizada com sucesso.
➢400 –Bad Request -> Erro na requisição (dados inválidos ou incompletos).
Ex.: enviar cadastro sem email ou senha.
➢401 –Unauthorized -> Usuário não autenticado.
Ex.: acessar rota protegida sem login/token.
Status HTTP: respostas de sucesso e erro em APIs
➢404 –Not Found -> Recurso ou rota não encontrada.
Ex.: acessar / users /99 quando esse usuário não existe.
➢405 –Method Not Allowed -> Método HTTP não permitido para a rota.
Ex.: usar DELETE em uma rota que aceita apenas GET.
➢409 –Conflict -> Conflito de dados (registro já existente).
Ex.: tentar cadastrar um email que já está no banco.

Noções de Segurança em Servidores
➢JWT (JSON Web Token)

Noções de Segurança em Servidores
➢Se alguém enviar: OR 1=1
➢O banco NÃO executa isso como lógica SQL. Ele interpreta literalmente como string : email
= "OR 1=1" 
➢Ou seja:
➢vira apenas um valor de campo
➢não altera a estrutura da query
➢não “quebra” o WHERE
➢Já na versão vulnerável (concatenação ): WHERE email = '" + email + “’  . O conteúdo entra 
direto no SQL e passa a fazer parte do comando.
